# ShardFlow V1 — Error Response Contract

**Document:** Error Response Specification  
**Product:** ShardFlow  
**Version:** V1.0  
**Status:** Active / Implementation Contract  
**Last Updated:** 2026-10-03  

---

# 1. Purpose

This document defines the standardized error response envelope and client-facing error semantics for ShardFlow V1.

All API responses generated by the ShardFlow Control Plane and Data Plane follow a predictable, machine-readable format.

---

# 2. Canonical Error Response Envelope

When an HTTP request to ShardFlow fails (HTTP status >= 400), the response body MUST use the following JSON structure:

```json
{
  "success": false,
  "message": "Human-readable summary message",
  "error": {
    "code": "ERROR_CODE",
    "message": "Detailed error explanation"
  }
}
```

### Field Definitions

| Field | Type | Required | Description |
| :--- | :--- | :---: | :--- |
| `success` | `boolean` | Yes | Always `false` for error responses. |
| `message` | `string` | Yes | Top-level human-readable message summarizing the failure. |
| `error` | `object` | Yes | Error details object. |
| `error.code` | `string` | Yes | Canonical, stable `SCREAMING_SNAKE_CASE` error code defined in `error-codes.md`. |
| `error.message` | `string` | Yes | Technical description explaining why the request failed. |

# 3. HTTP Status Codes & Mapping

ShardFlow uses standard HTTP status code semantics:

| HTTP Status | Category | Meaning | Example Error Codes |
| :---: | :--- | :--- | :--- |
| **400** | Bad Request | Request is malformed or missing required parameters. | `INVALID_REQUEST`, `MISSING_REQUIRED_FIELD`, `INVALID_FIELD`, `INVALID_FIELD_TYPE`, `INVALID_FIELD_FORMAT`, `INVALID_ID` |
| **401** | Unauthorized | Authentication is missing, invalid, or expired. | `AUTHENTICATION_REQUIRED`, `INVALID_AUTH_TOKEN`, `AUTH_TOKEN_EXPIRED`, `INVALID_API_KEY`, `API_KEY_REVOKED`, `API_KEY_EXPIRED`, `PROJECT_RESOLUTION_FAILED` |
| **403** | Forbidden | Principal is authenticated but lacks required permission. | `ACCESS_DENIED`, `PROJECT_ACCESS_DENIED`, `RESOURCE_ACCESS_DENIED`, `TENANT_ACCESS_DENIED`, `CLIENT_SHARD_SELECTION_NOT_ALLOWED` |
| **404** | Not Found | Requested project, shard, mapping, or entity does not exist. | `PROJECT_NOT_FOUND`, `API_KEY_NOT_FOUND`, `SHARD_NOT_FOUND`, `ROUTING_CONFIGURATION_NOT_FOUND`, `TENANT_MAPPING_NOT_FOUND`, `TENANT_NOT_MAPPED`, `TENANT_RESOLUTION_FAILED`, `DATABASE_DOCUMENT_NOT_FOUND` |
| **409** | Conflict | Operation conflicts with current resource state. | `PROJECT_ALREADY_EXISTS`, `PROJECT_DISABLED`, `API_KEY_ALREADY_REVOKED`, `SHARD_ALREADY_EXISTS`, `SHARD_DISABLED`, `TENANT_MAPPING_ALREADY_EXISTS`, `DATABASE_DUPLICATE_KEY`, `RESOURCE_DISABLED`, `RESOURCE_STATE_CONFLICT` |
| **413** | Payload Too Large | Request body or document size exceeds configured limit. | `REQUEST_TOO_LARGE`, `DOCUMENT_TOO_LARGE` |
| **422** | Unprocessable Entity | Payload is structurally valid JSON but semantically invalid. | `ROUTING_CONFIGURATION_INVALID`, `UNSUPPORTED_ROUTING_STRATEGY`, `INVALID_TENANT_MAPPING`, `DATA_OPERATION_NOT_SUPPORTED`, `INVALID_DATA_OPERATION`, `INVALID_COLLECTION`, `INVALID_DOCUMENT`, `INVALID_FILTER`, `INVALID_UPDATE`, `UNSUPPORTED_OPERATOR`, `INVALID_OPERATOR`, `OPERATOR_NOT_ALLOWED`, `UNSUPPORTED_OPTION`, `INVALID_OPTION`, `INVALID_LIMIT`, `INVALID_SKIP`, `INVALID_SORT`, `INVALID_PROJECTION`, `DATABASE_QUERY_INVALID` |
| **429** | Too Many Requests | Rate limit exceeded. | `RATE_LIMIT_EXCEEDED` |
| **500** | Internal Server Error | Unhandled server or database error. | `INTERNAL_ERROR`, `API_KEY_CREATION_FAILED` |
| **502** | Bad Gateway | Failure communicating with customer MongoDB shard or credential error. | `SHARD_CONNECTION_FAILED`, `SHARD_CREDENTIALS_INVALID`, `DATABASE_OPERATION_FAILED` |
| **503** | Service Unavailable | Required internal service or mapped shard is unavailable. | `SHARD_UNAVAILABLE`, `SHARD_HEALTH_CHECK_FAILED`, `MAPPED_SHARD_UNAVAILABLE`, `SHARD_RESOLUTION_FAILED`, `CONNECTION_POOL_UNAVAILABLE`, `CONNECTION_MANAGER_ERROR`, `SERVICE_UNAVAILABLE`, `AUTH_PROVIDER_UNAVAILABLE`, `EMAIL_PROVIDER_UNAVAILABLE` |
| **504** | Gateway Timeout | Database connection or query timeout. | `SHARD_CONNECTION_TIMEOUT`, `DATABASE_OPERATION_TIMEOUT`, `CONNECTION_ACQUISITION_TIMEOUT` |

---

# 4. Serialization & Content Rules

1. **Content-Type Header:** All API error responses MUST include `Content-Type: application/json`.
2. **Sanitization:** Error responses MUST NEVER expose raw database credentials, connection strings, API key hashes, internal stack traces, filesystem paths, or Supabase service secrets.
3. **Machine Readability:** Client SDKs and frontend applications MUST programmatically inspect `error.code` rather than parsing `error.message`.
